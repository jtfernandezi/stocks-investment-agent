### Lever 5 — Guardrails

**hold_days = 30 fallback bug:** `post_mortem_build_input.js` lines 38–45 compute `actualEntryDate` as:
1. `posEntry.entry_date` (from `Load Position Entry` reading `position_metadata`) if available
2. Otherwise: `exitDate - 30 days` (hardcoded fallback)

For trailing stop exits where `posEntry.entry_date` is unavailable (e.g., same-session stops where metadata timing is tight, or mismatches in Load Position Entry), the code falls back to the 30-day approximation. Four trades show this bug: IREN (held 7 days, shows 30), ON (8 days, shows 30), SCCO (8 days, shows 30), AMAT (<1 day, shows 30).

The `webhook` payload from `build_ts_pm_payload.js` **does** pass `entry_date: entry_date.toString().substring(0, 10)` — the correct date from `position_metadata` at detection time. The code simply never tries `webhook.entry_date` before falling back to the 30-day default.

**Fix:** Add `webhook.entry_date` as an intermediate fallback (see Type A #1 below).

**Stop performance:**

- ON/SCCO: -2.27%/-2.44% (tight stops, within band)
