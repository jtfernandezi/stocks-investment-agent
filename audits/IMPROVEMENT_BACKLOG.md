# Improvement Backlog — Initiatives Register

Living, ranked list of ideas for making the fund better, plus the **Lever 7b R&D research agenda** (below). Maintained by the weekly audit (`automation/weekly_audit_prompt.md`) — it adds evidence-grounded ideas, re-ranks each week, dedups, advances maturity grades, and tracks whether applied ideas actually worked.

**The audit now CODES some of these into PRs** (reworked 2026-06-11). Each item maps to a tier:
- **`[A]`** tunable fix · **`[B-code]`** isolated, code-only, low-blast-radius change (no n8n wiring) → both get **coded into PRs** (human merges).
- **`[B-spec]`** needs n8n wiring, or is a strategy/judgment call, or isn't verifiable yet → **spec only**, built deliberately by a human. Strategies stay here until a backtest harness exists.

**Status legend:** `proposed` → `coded PR#<n>` → `merged` → `worked` / `didn't` / `dropped`
**Maturity (R&D agenda):** `speculative` (plausible, no evidence) → `promising` (some supporting evidence) → `evidence-backed` (data clearly supports it; if isolated/code-only, eligible to become a `[B-code]` PR)

### Notes for the auditor
- **Dedup:** before adding an idea, check it isn't already a row above (even reworded). If it is, update its evidence/maturity/rank instead of adding a duplicate.
- **Advance, don't re-brainstorm:** each week move maturity grades with fresh evidence (`speculative → promising → evidence-backed`) or kill an idea. Honest "still speculative, no new evidence" is fine — do NOT manufacture novelty.
- **Promote to code carefully:** an initiative becomes a `[B-code]` PR only when `evidence-backed` AND isolated/code-only (no n8n wiring, low blast radius). Strategy stays `[B-spec]` until the backtest harness exists.
- **Close the loop:** when an item is coded into a PR, record `coded PR#<n>`; after merge, the next audits judge whether the targeted metric improved and set `worked` / `didn't`.
- **Tag honestly:** Risk = risk-to-stability of the live fund if implemented. High-impact + low-risk rises to the top.
